## 1. MVP 점수 정규화 제거

### 문제
세션 스탯 탭에서 1등 점수를 10점으로 정규화하여 표시. 1골로 MVP인 세션이나 5골+3도움으로 MVP인 세션이나 둘 다 10.0으로 보여 기여도 차이가 사라짐. 시즌 랭킹(원시 점수)과 세션 스탯(정규화 점수)이 서로 다른 체계.

### 변경
- `web/src/components/session/stats-tab.tsx:146-150` 정규화 로직 제거
- 원시 점수 그대로 표시 (골×2 + 도움×1.5 + 수비×0.5 + 우승×1.5)
- 시즌 랭킹과 동일한 공식 적용

### 영향 범위
- `stats-tab.tsx` 1파일

## 2. 세션 삭제 기능

### 문제
잘못 생성한 세션을 삭제할 수 없음 (예: 3월 25일자 세션을 실수로 생성).

### 요구사항
- Hard delete (DB에서 완전 삭제)
- 관리자(admin)만 삭제 가능
- 모든 세션 상태에서 삭제 가능 (제한 없음)
- 삭제 전 확인 모달 필수

### API
- `DELETE /sessions/:id` 엔드포인트 신규 추가
- 관련 테이블 순서대로 삭제 (트랜잭션):
  1. `match_events` (match_id 기준)
  2. `player_match_stats` (match_id 기준)
  3. `matches` (session_id)
  4. `team_members` (team_id 기준)
  5. `teams` (session_id)
  6. `session_mvp_votes` (session_id)
  7. `session_mvp_results` (session_id)
  8. `session_payments` (session_id)
  9. `settlements` (session_id)
  10. `attendance` (session_id)
  11. `player_ratings` (session_id)
  12. `session_rsvp` (CASCADE로 자동)
  13. `sessions` (id)

### 프론트엔드
- 웹: 세션 상세 페이지에 삭제 버튼 (관리자만 표시)
- Flutter: 세션 상세 화면에 삭제 옵션

### 영향 범위
- `api/src/routes/sessions.ts` — DELETE 엔드포인트 추가
- `web/src/app/(main)/admin/sessions/page.tsx` 또는 세션 상세 — 삭제 UI
- `app/lib/screens/session_detail_screen.dart` — 삭제 UI

## 3. 웹 페이지 재구조화

### 문제
"내 것", "클럽 것", "관리 것"이 /profile과 /club에 뒤섞여 UX 혼란.

### 새 구조

#### `/profile` — 순수 계정 관리
- 아바타 + 이름 + 역할 배지
- 계정 정보 (이메일, 닉네임, 비밀번호)
- 신체 정보 (키, 몸무게, 출생연도, 전화번호)
- 소셜 계정 (Google 연동/해제)
- 로그아웃

**제거 항목 (→ /club으로 이동):**
- 시즌 스탯 카드
- 클럽 바로가기 카드
- 구독 플랜 정보

#### `/club` — 클럽 정보 (읽기 전용, 모든 멤버)
- 클럽 히어로 카드 (이름, 로고, 멤버수, 시즌, 플랜)
- 초대 코드 (보기/복사만, 재발급은 /admin/settings)
- 내 시즌 스탯 (MVP 순위, 골/도움/수비/MVP 수, 승무패, 경기수)
- 구독 플랜 정보
- 바로가기 (세션, 랭킹, 상세 기록)

**제거 항목 (→ /admin/settings로 이동):**
- 초대코드 재발급
- 로고 업로드/삭제
- MVP 투표 토글

#### `/admin/settings` — 클럽 설정 (관리자 전용, 신규 탭)
기존 /admin 탭 네비게이션(세션/선수/랭킹/알림/유저)에 **설정** 탭 추가:
- 클럽 로고 업로드/삭제
- 초대 코드 재발급
- 기능 토글 (MVP 투표, 자동 정산 알림, 세션 생성 알림)
- 클럽 정보 수정 (이름, 설명, 시즌 시작월)
- 위험 구역 (클럽 삭제)

### 디자인
- 목업 파일: `docs/mockup-redesign.html`
- 디자인 톤: 기존 브랜드(#2ECC71 + 다크 슬레이트) 유지
- 카드 기반 레이아웃, 정보 계층 명확화

### 영향 범위
- `web/src/app/(main)/profile/page.tsx` — 시즌스탯/클럽카드/구독 제거
- `web/src/app/(main)/club/page.tsx` — 관리자 기능 제거, 시즌스탯 추가
- `web/src/app/(main)/admin/settings/page.tsx` — 신규 생성

## 5. 온보딩 & 컨텍스트 팁 시스템

### 문제
기능이 많아서 사용자가 어디서 뭘 해야 할지 모름.

### 구현 방향

#### 5-1. 첫 사용 온보딩 (1회)
- 앱 첫 실행 시 3~4장 슬라이드
- 주요 기능 소개: 세션 경기 기록 / 랭킹 순위 확인 / 클럽 멤버 관리
- 건너뛰기 가능
- `SharedPreferences`로 완료 여부 저장

#### 5-2. 컨텍스트 팁 — 코치마크 (각 화면 첫 방문)
- 특정 버튼/영역을 스포트라이트 강조 + 말풍선 설명
- 예시:
  - 클럽 탭 첫 방문 → 멤버 카드: "선수를 탭하면 능력치와 기록을 볼 수 있어요"
  - 세션 상세 첫 방문 → 경기 탭: "여기서 골, 수비 등 경기 이벤트를 기록하세요"
  - 랭킹 탭 첫 방문 → 세그먼트: "통계, 명예의 전당도 여기서 확인!"
  - 관리자 첫 방문 → 톱니바퀴: "클럽 설정은 여기서"
- 패키지: `tutorial_coach_mark`

#### 5-3. 빈 상태(Empty State) 가이드
- 세션 없을 때: "첫 세션을 만들어보세요!" + 만들기 버튼
- 랭킹 없을 때: "경기를 완료하면 랭킹이 자동 생성됩니다"
- 멤버 없을 때: "초대 코드를 공유해서 멤버를 초대하세요"

### 적용 범위
- Flutter 앱 전용 (웹은 현재 불필요)

## 6. 구글 로그인 OAuth 점검

### 현황
- API: ID 토큰을 클라이언트에서 받아 `tokeninfo` 엔드포인트로 검증
- Google Sign-In SDK가 ID 토큰을 직접 발급하는 방식은 Google 공식 지원 패턴이므로 OAuth 위반 아님
- 단, `tokeninfo` 대신 `google-auth-library`로 검증하는 게 권장됨

### 변경
- `api/src/routes/auth.ts` — tokeninfo 검증을 `google-auth-library` 사용으로 변경
- 이메일 기반 자동 연동 로직 보안 검토 (계정 탈취 위험)

### 영향 범위
- `api/src/routes/auth.ts`
- `api/package.json` — google-auth-library 추가

## 7. 알림 자동화

### 구현 대상
- **세션 생성 알림**: 새 세션 생성 시 전체 멤버에게 자동 알림
- **정산 미완료 리마인더**: 세션 종료 후 미정산 시 자동 리마인드
- 관리자 설정에서 각 알림 on/off 토글 가능 (/admin/settings)

### 추가 논의 필요
- 알림 전달 방식 (앱 푸시? 웹 알림? 카카오톡?)
- 자동화 트리거 타이밍 (세션 종료 후 N시간? Cron?)

### 영향 범위
- API: 알림 자동 발송 로직
- DB: 클럽 설정 테이블에 알림 토글 컬럼 추가
- 웹/앱: /admin/settings에 토글 UI
